## 3. 用例详细描述

### UC-01 一键保护工程（端到端）

- **主要参与者**：AI Agent
- **触发**：Agent 需要保护某个代码工程
- **前置条件**：工程可本地构建；用户对目标拥有合法所有权（FR-A6）
- **主成功场景**：
  1. Agent 调用 `anti_rea.scan`（或 `anti-rea scan`），得到 `asset_manifest`；
  2. Agent 调用 `anti_rea.plan`，按敏感度与预算得到 `protection_policy`；
  3. Agent 调用 `anti_rea.protect`，执行变换得到保护产物；
  4. Agent 调用 `anti_rea.verify`，确认功能保持；
  5. Agent 调用 `anti_rea.attack_sim`，得到 `eval_report`；
  6. Agent 调用 `anti_rea.report`，产出保护报告。
- **扩展 / 异常**：
  - 2a. 存在策略冲突 / 覆盖缺口 → 返回告警，Agent 调整预算或敏感度后重试（FR-B5）；
  - 3a. 变换过程中功能校验失败 → 按配置回滚或中止（FR-C12、FR-D7）；
  - 5a. 指标未达目标 → 触发策略调整或进化（FR-F2）。
- **后置条件**：得到保护产物 + 报告 + 可复现元数据（FR-G1/G2）
- **关联需求**：FR-A1…A6、FR-B1…B6、FR-C1…C12、FR-D6、FR-E1…E7、FR-G1

### UC-02 CI 内嵌保护

- **主要参与者**：构建 / 发布工程师
- **触发**：构建流水线在编译后需要自动施加保护
- **前置条件**：项目使用受支持的构建系统；已配置保护策略
- **主成功场景**：
  1. 在 CMake / Cargo / npm / Python 构建流程中挂载 Anti-REA 步骤（FR-D2…D5）；
  2. 编译产出中间产物；
  3. Anti-REA 对白名单资产施加变换（FR-C6）；
  4. 运行验证，通过则继续打包分发；失败按配置中止（FR-D7）；
  5. 输出保护报告与制品。
- **扩展 / 异常**：
  - 4a. 功能验证失败 → 构建失败，退出码非零，日志可定位（NFR-11）；
  - 1a. 想要每次构建不同变体 → 启用 MTD（FR-B4）。
- **后置条件**：CI 产出受保护且验证通过的分发制品
- **关联需求**：FR-D1…D7、FR-E1/E2、FR-B4、NFR-11

### UC-03 敏感资产扫描与分级

- **主要参与者**：安全工程师 / AI Agent
- **触发**：需要了解工程中哪些资产需要保护
- **前置条件**：可访问目标工程源码 / 二进制
- **主成功场景**：
  1. 执行扫描，识别语言 / 构建系统 / 目标平台（FR-A1）；
  2. 通过字符串 / 函数级 / 数据流三类手段识别敏感资产（FR-A2）；
  3. 自动分级 P0–P3 并给出证据（FR-A3）；
  4. 识别开源组件并输出 SBOM，标记为 P3（FR-A4）；
  5. 输出 `asset_manifest.json` 并通过 Schema 校验（FR-A5）。
- **扩展 / 异常**：
  - 1a. 所有权不明 / 疑似恶意 → 拒绝执行并报告（FR-A6）；
  - 3a. 自动分级不准 → 用 `assets.yaml` 人工覆盖（FR-A7）。
- **后置条件**：得到可解释、可校验的资产清单
- **关联需求**：FR-A1…A7

### UC-04 策略定制与预算约束

- **主要参与者**：安全工程师
- **触发**：需要在安全强度与性能开销之间取得平衡
- **前置条件**：已有 `asset_manifest`
- **主成功场景**：
  1. 加载策略模板库，按敏感度匹配策略组合（FR-B1、FR-B2）；
  2. 设定性能预算，系统预测开销并优化组合（FR-B3）；
  3. 对 P0 资产启用 MTD 多变体（FR-B4）；
  4. 检测冲突 / 缺口并告警（FR-B5）；
  5. 输出 `protection_policy.yaml` 并通过校验（FR-B6）。
- **扩展 / 异常**：
  - 2a. 无法在预算内达成目标强度 → 告警并给出可选降级方案；
  - 3a. 变体数过高导致构建时间过长 → 下调 `variant_count`。
- **后置条件**：得到可执行、可校验的防护策略
- **关联需求**：FR-B1…B6

### UC-05 功能保持验证

- **主要参与者**：构建工程师 / AI Agent
- **触发**：变换完成后需确认功能未被破坏
- **前置条件**：已有保护产物；目标工程提供测试套件或可自动生成
- **主成功场景**：
  1. 对受保护产物运行原工程测试套件（FR-E1）；
  2. 对关键接口执行差分 fuzz，比对原版与保护版行为（FR-E1、NFR-03）；
  3. 测量运行时开销并与预算比对（FR-E2）；
  4. 生成验证报告。
- **扩展 / 异常**：
  - 1a. 测试失败 → 定位到具体变换 / 资产（NFR-11），按策略回滚（FR-C12）；
  - 3a. 开销超预算 → 告警，建议降低变换强度（FR-B3）。
- **后置条件**：确认功能等价与开销合规，或定位失败点
- **关联需求**：FR-E1、FR-E2、NFR-03、FR-C12

### UC-06 攻击模拟与效果评估

- **主要参与者**：安全工程师
- **触发**：需要量化防护效果是否达到「成本 > 收益」
- **前置条件**：已有保护产物；运行环境提供可用的 LLM（不绑定固定供应商）
- **主成功场景**：
  1. 静态攻击模拟：Ghidra Headless 反编译 + LLM 语义恢复，在**独立会话**中执行并记录上下文消耗率（FR-E3）；
  2. 动态攻击模拟：沙箱运行，尝试内存转储 / 调试（FR-E4）；
  3. 跨版本复用攻击模拟（FR-E5）；
  4. 计算六项量化指标并写入时序库（FR-E6）；
  5. 生成评估报告（FR-E7）。
- **扩展 / 异常**：
  - 1a. 批量反编译成功率过低 → 告警并记录（FR-E3 验收标准 ≥ 95%）；
  - 4a. 指标未达标 → 触发回归 / 策略调整（FR-E8、FR-F2）。
- **判定口径（S0 决策 OI-03）**：给 LLM 一个独立会话对受保护产物做 REA，若**上下文消耗达到 90% 仍未成功**，即判本次保护**通过**，与具体模型无关。
- **后置条件**：得到量化对抗评估结论
- **关联需求**：FR-E3…E7、NFR-02

### UC-07 策略进化与迁移

- **主要参与者**：维护者 / AI Agent
- **触发**：发现新弱点，或希望复用既有有效策略
- **前置条件**：已有历史评估数据与策略知识库
- **主成功场景**：
  1. 多 LLM 并行探测，评估策略跨模型泛化性（FR-F1）；
  2. 记录弱点并给出 / 执行策略调整（FR-F2）；
  3. 运行策略遗传进化，选择更优组合（FR-F3）；
  4. 将有效策略入库，向相似项目迁移推荐（FR-F4）。
- **扩展 / 异常**：
  - 1a. LLM 成本 / 配额受限 → 用小模型预筛 + 缓存（风险应对）；
  - 3a. 进化后指标劣化 → 回退到上一代策略。
- **后置条件**：策略库更新，防护能力维持或提升
- **关联需求**：FR-F1…F4

### UC-08 单文件 / 单函数快速加固

- **主要参与者**：开发者
- **触发**：只希望对某个关键函数快速加固，而非全工程
- **前置条件**：可指定目标文件 / 函数
- **主成功场景**：
  1. 通过 `assets.yaml` 直接标注目标（FR-A7）；
  2. 生成仅覆盖该目标的策略（FR-C6）；
  3. 通过 CLI 执行变换并验证（FR-D1）。
- **扩展 / 异常**：
  - 1a. 目标位于开源文件中 → 拒绝变换（FR-A4 / CQ-01）。
- **后置条件**：得到最小范围的加固产物
- **关联需求**：FR-A7、FR-C6、FR-D1

### UC-09 效果趋势追踪与回归监控

- **主要参与者**：维护者
- **触发**：常规回归周期到达，或引擎 / 策略变更后
- **前置条件**：已有时序数据库与基准题库
- **主成功场景**：
  1. 运行攻击模拟基准回归（FR-E8）；
  2. 更新六项指标时序（FR-E6）；
  3. 指标退化时告警并触发策略库更新（FR-F2）。
- **扩展 / 异常**：
  - 1a. 基准本身失效（如 LLM 版本变化）→ 更新基准题库与 REA 能力追踪表。
- **后置条件**：防护效果趋势可见，退化及时暴露
- **关联需求**：FR-E6、FR-E8

## 4. 端到端主场景（UC-01 时序）

```text
AI Agent                     Anti-REA Skill                     外部系统
   │                              │                                │
   │─ scan ─────────────────────▶│ 扫描工程 ──────────────────────▶│ (无)
   │◀─ asset_manifest ───────────│                                │
   │─ plan ─────────────────────▶│ 匹配策略 + 预算优化             │
   │◀─ protection_policy ────────│                                │
   │─ protect ──────────────────▶│ LLVM Pass / VM / WBC ─────────▶│ LLVM
   │◀─ artifacts + 变换日志 ──────│                                │
   │─ verify ───────────────────▶│ 测试套件 + 差分 fuzz            │
   │◀─ verification_report ──────│                                │
   │─ attack_sim ───────────────▶│ 反编译 + LLM 语义恢复 ─────────▶│ Ghidra / LLM
   │◀─ eval_report ──────────────│                                │
   │─ report ───────────────────▶│ 生成报告                        │
   │◀─ protection_report ────────│                                │
```

**主路径验收**：全流程可在 Agent 驱动下无人值守完成，且每步产物通过 Schema 校验（FR-A5 / B6 / E7）。
