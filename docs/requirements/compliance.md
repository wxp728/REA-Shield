# Anti-REA Skill 合规与边界需求清单

## 文档信息

- **文档版本**：v1.1
- **创建日期**：2026-10-15
- **阶段**：S0 立项与需求分析（交付物 RQ-06）
- **上游依据**：`SRS.md` v1.0 §6、`plan/anti-rea-plan.md` §6（风险）、`plan/anti-rea-project-plan.md` §10.2
- **用途**：把合规与使用边界约束固化为可验收需求，作为 S5 合规审查的检查依据。

---

## 1. 范围

本清单覆盖四类约束：**开源许可证（CQ-01）**、**出口管制（CQ-02）**、**使用边界（CQ-03）**、**EDR 误报缓解（CQ-04）**，以及 SRS 细化补充的 **数据保密与出站控制（CQ-05）**。

产品定位本身即构成一项合规前提：Anti-REA 只用于**保护合法所有者拥有或有权处理的代码**，不用于规避第三方正当的逆向分析或实施恶意行为。

---

## 2. CQ-01 开源许可证合规

| 项 | 要求 |
| :--- | :--- |
| 核心原则 | **不得对开源组件施加任何变换**（避免产生许可证衍生义务 / 违反许可条件） |
| 识别 | 扫描阶段识别开源组件与第三方依赖，标记为 P3 并跳过变换（FR-A4） |
| 声明保留 | 保护产物中保留原许可证声明与版权信息 |
| 物料清单 | 输出 SBOM（SPDX 或 CycloneDX），含许可证字段 |
| 依赖合规 | 工具自身依赖亦须做许可证审查与 SBOM（NFR-09） |
| 验证 | `TC-CQ1`：对含开源文件的目标工程，开源文件字节级零改动；SBOM 字段完整 |

**风险**：将开源代码误判为自研并混淆 → 许可证违规。**应对**：识别基于文件路径白名单 + 依赖清单 + 代码指纹交叉确认，宁可误标 P3 不误混淆。

---

## 3. CQ-02 出口管制

| 项 | 要求 |
| :--- | :--- |
| 核心原则 | 加密强度按目标市场分级配置，避免违反目标市场的加密出口 / 进口法规 |
| 分级配置 | 提供加密强度档位（如强度等级 A/B/C），映射到 WBC / 虚拟化中的密码学参数 |
| 市场清单 | 维护「目标市场 → 允许强度」映射表（具体清单为待决问题 OI-04） |
| 审计日志 | 记录加密强度配置、目标市场、应用时间，形成可审计日志 |
| 验证 | `TC-CQ2`：切换市场配置后产物强度参数随之变化，且审计日志完整 |

**风险**：默认强度在特定市场违规。**应对**：默认取最保守档位，明确要求用户声明目标市场后才可提升强度。

---

## 4. CQ-03 使用边界（滥用防范）

| 项 | 要求 |
| :--- | :--- |
| 核心原则 | 仅用于保护合法所有者的代码；拒绝疑似恶意或所有权不明的目标 |
| 拒绝执行 | 触发拒绝条件时中止流程并生成拒绝报告，不产出任何变换产物（FR-A6） |
| 留痕 | 拒绝行为记录时间、目标指纹、触发原因 |
| 使用条款 | 文档中明示许可用途与禁止用途（恶意软件加固、规避安全检测等） |
| 验证 | `TC-CQ3`：对标注为疑似恶意的目标，流程中止且无产物；拒绝记录可查 |

**风险**：工具被用于加固恶意软件。**应对**：显式用途声明 + 所有权确认步骤 + 拒绝留痕；从产品定位上不提供规避检测能力。

---

## 5. CQ-04 EDR 误报缓解

| 项 | 要求 |
| :--- | :--- |
| 核心原则 | 保护产物不应被主流 EDR 大面积误杀，避免正常分发受阻 |
| 签名支持 | 为产物提供签名支持能力与签名指引 |
| 白名单流程 | 提供面向主流 EDR 厂商的白名单 / 申诉流程文档 |
| 兼容性测试 | 误报情况纳入兼容性测试矩阵（NFR-10） |
| 验证 | `TC-CQ4`：对代表性产物在主流 EDR 上做误报测试并给出结论 |

**风险**：混淆 / 虚拟化产物触发启发式查杀。**应对**：把「误报率」纳入变换适应度约束，避免过度畸形化；先签名再分发。

---

## 6. CQ-05 数据保密与出站控制（SRS 细化补充）

| 项 | 要求 |
| :--- | :--- |
| 核心原则 | 扫描 / 变换默认**完全本地**执行；用户代码默认不出本机 |
| LLM 出站 | 仅攻击模拟与策略进化需要外部 LLM，且必须**显式开启** |
| 替代方案 | 支持私有 / 本地模型；支持对出站内容做脱敏（去除路径、注释、字符串常量） |
| 出站清单 | 每次出站记录发送内容摘要、目标供应商、时间，形成审计记录 |
| 验证 | `TC-CQ5`：默认配置下无任何网络出站；开启后出站内容符合脱敏策略 |

**风险**：用户源码 / 反编译文本经 LLM API 外泄。**应对**：本地优先 + 显式开启 + 脱敏 + 出站审计四重控制。

**评估 LLM 说明（S0 决策 OI-03）**：评估环节**不绑定固定供应商**，使用 Agent 运行环境所提供的 LLM（含调用本工具的会话模型）。出站控制据此调整为：模型由运行环境决定；评估须在**独立会话**中进行；对发送内容摘要与上下文消耗留痕（判定口径为「独立会话上下文消耗 ≥ 90% 仍未成功 REA 即判通过」）。

---

## 7. 审计与留痕（跨项要求）

以下事件须写入审计日志（配合 NFR-11 可观测性）：

- 拒绝执行事件（CQ-03）；
- 加密强度与目标市场配置变更（CQ-02）；
- LLM 出站事件（CQ-05）；
- 开源组件识别结果与跳过变换记录（CQ-01）。
