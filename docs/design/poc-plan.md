## 2. PoC-1：LLVM Pass 可行性

- **目标**：确认在目标 LLVM 版本上编写自定义 FunctionPass、遍历与改写 IR 顺畅，且改写后不破坏语义。
- **环境**：LLVM 18+（锁定版本）；C++ 工具链；样例 C 工程（含 2–3 个函数与单元测试）。
- **步骤**：
  1. 搭建 Pass 插件骨架（`register_plugin`、`PassBuilder` 注册）；
  2. 实现最简 CFF：基本块提取 → 状态编号 → switch 调度器；
  3. 对样例函数施加变换，编译并运行单元测试；
  4. 记录遇到的 IR 版本 / 内建函数 / ABI 问题。
- **通过标准**：样例函数变换后可编译、可运行、单元测试全过；Pass 加载与注册流程跑通。
- **产出**：PoC 报告（含代码骨架与问题清单）→ 回写 ADR-001。
- **失败备选**：更换 LLVM 版本；或降级为「先做指令级 / 二进制级混淆」。

## 3. PoC-2：Ghidra Headless 自动化

- **目标**：确认 Headless 模式能批量反编译，并稳定产出可喂给 LLM 的文本。
- **环境**：Ghidra（锁定版本）+ JDK；若干样例二进制（含 P0 类函数）。
- **步骤**：
  1. 编写 Headless 脚本（分析 → 反编译 → 导出函数级文本）；
  2. 对样例集批处理，统计成功率与耗时；
  3. 检查导出文本对 LLM 的可读性（函数边界、伪代码质量）。
- **通过标准**：批量反编译成功率 ≥ 95%；导出文本结构完整、可被 LLM 直接消费。
- **产出**：PoC 报告 + 适配层接口草案 → 回写 ADR-006。
- **失败备选**：改用 Ghidra 的其它 API / 备用反编译后端；调整适配层抽象。

## 4. PoC-3：DEAP 策略进化原型

- **目标**：确认用 DEAP 表达「策略基因」并跑通进化循环。
- **环境**：Python 3.11+；DEAP；伪造的适应度函数（或少量真实评估数据）。
- **步骤**：
  1. 定义策略基因编码（资产 → 策略组合 + 参数）；
  2. 定义适应度（防护得分 − 开销惩罚，防作弊式优化）；
  3. 跑一轮：种群初始化 → 评估 → 交叉变异 → 选择；
  4. 检查收敛性与结果可解释性。
- **通过标准**：完成一轮完整进化循环；防护得分不劣化；运行时间可接受。
- **产出**：PoC 报告 + 基因编码草案 → 支撑 FR-F3 / ADR-005。
- **失败备选**：改用更简单的爬山 / 贪心搜索替代遗传算法。

## 5. PoC-4：白盒密码查找表编码

- **目标**：验证「自研查找表编码」路线可落地且性能可接受（ADR-003 的确认依据）。
- **环境**：C/C++；样例 AES 实现。
- **步骤**：
  1. 将 S-box 编码为查找表，叠加编码变换（输入 / 输出编码）隐藏查表规律；
  2. 实现运行时密钥重构与用后销毁；
  3. 自测加解密正确性；测量相对性能开销；
  4. 静态检查：代码中不出现明文密钥常量。
- **通过标准**：加解密自洽；无明文密钥常量；性能开销在可接受范围。
- **产出**：PoC 报告 + 编码方案草案 → 回写 ADR-003（确认或改走 Chow）。
- **失败备选**：改用更简单 / 更复杂的编码方案；或把 FR-C10 降级。

## 6. 结论汇总与出口

> 执行环境：RHEL 系 Linux（x86_64）；LLVM/clang 18.1.8；Ghidra 12.1.4 + JDK 21 + PyGhidra 3.1.0；
> Python 3.11.9 + DEAP 1.4；GCC 7.3。PoC 可执行代码与证据见仓库 `poc/` 目录。
> 执行日期：2026-10-15。

| PoC | 结论 | 证据 | 回写位置 | 日期 |
| :--- | :--- | :--- | :--- | :--- |
| PoC-1 | ✅ 通过 | `poc/poc1-llvm-pass/`：New PM 插件对 5 个样例函数完成 CFF（`.text` 1074→2930/3010 字节），两条加载路径（`clang -fpass-plugin`、`opt -passes=reg2mem,cff-flatten`）变换后可编译、可运行、单元测试全过 | ADR-001 | 2026-10-15 |
| PoC-2 | ✅ 通过 | `poc/poc2-ghidra-headless/`：PyGhidra 批量反编译 3 个样例二进制（O0/O2/stripped），成功率 57/57 = 100%（≥ 95%），逐函数伪代码文本可供 LLM 消费 | ADR-006 | 2026-10-15 |

**关键发现（供架构与后续阶段参考）**
- PoC-1：CFF 会使派发块可绕过任意基本块，从而**破坏跨基本块的 SSA 支配关系**，因此必须先 `reg2mem`（把跨块值降级到内存）再平坦化；且 `clang -S -emit-llvm` 的文本输出**不含** OptimizerLast 扩展点的效果，验证应以最终二进制或 `opt` 路径为准。**变换应在优化流水线末端执行**，否则会被后续 SimplifyCFG 等还原。
- PoC-2：Ghidra 12 已**移除内置 Jython**，批量脚本必须走 **PyGhidra（CPython）** 或 Java；适配层应以 PyGhidra 为基座。
- PoC-3：进化循环对「策略基因（策略开关 + 参数）」表达顺畅；适应度为**代理模型**，真实得分待评估验证层回填。
- PoC-4：轻量查找表编码满足「加解密自洽 / 无明文密钥 / 开销可控」，但抗静态分析强度有限（与 ADR-003 threat model 一致）。

**M1 出口要求**：四项 PoC 均有明确结论；不通过项必须有调整后的方案或需求变更记录。
→ **四项全部通过，无需求变更。满足 M1 出口要求（见 `HLD.md §11`）。**
