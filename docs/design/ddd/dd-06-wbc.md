## 1. 目标与范围

设计 v1.0 白盒密码模块：**查找表编码方案**、**密钥生命周期**、**威胁模型边界**。路线为 ADR-003 选定的**自研轻量查找表编码**（PoC-4 已验证）；Chow 白盒留作后续增强。

## 2. 方案概览

```mermaid
flowchart LR
  SEED[seed] --> TAB[编码表生成<br/>in_enc/out_enc/ETab]
  TAB --> RT[运行期: 密钥份额 xor 重构]
  RT --> RK[轮密钥扩展]
  RK --> USE[加密/解密<br/>经编码表 SubBytes]
  USE --> WIPE[用后安全清零]
```

- **不动算法语义**：输出与标准 AES-128 一致（PoC-4 对齐 FIPS-197）；
- **隐藏内容**：S-box 不以明文规律出现；密钥不以明文常量出现；表结构经双射编码打散；
- **可复现**：编码表由 `seed` 生成（NFR-04）。

## 3. 查找表编码方案（FR-C10）

### 3.1 基础编码（v1.0，PoC-4 已实现）

```text
in_enc, out_enc : 随机双射 (256)
ETab[i]         = out_enc[ sbox[ in_enc[i] ] ]      # 编码 S-box
SubBytes(x)     = out_enc_inv[ ETab[ in_enc_inv[x] ] ]
```

- **双射编码**打散 S-box 的输入/输出，使 `ETab` 不呈现标准 S-box 的可识别统计特征；
- **S-box 生成而非硬编码**：运行期由 GF(2⁸) 逆 + 仿射变换生成，避免二进制中出现明文 S-box 常量（PoC-4 做法）。

### 3.2 算法覆盖

| 算法 | v1.0 | 说明 |
| :--- | :--- | :--- |
| AES-128 | ✅ | PoC-4 已验证 |
| SM4 | Should | 复用同一编码框架（SM4 S-box 替换）|
| AES-192/256 | 扩展 | 轮密钥扩展适配 |

### 3.3 增强方向（后续版本）

- **Chow 风格 T-box**：把 SubBytes+ShiftRows+MixColumns 融合为宽表，并做输入/输出编码级联（更强的白盒强度，代价是体积与设计复杂度）；
- 需在威胁模型允许范围内评估收益/成本后再升级（保持与 SRS §2.2 边界一致）。

## 4. 密钥生命周期

| 阶段 | 设计 |
| :--- | :--- |
| **静态存储** | 密钥以**两个份额** `share_a`/`share_b` 存放；真实密钥 = `share_a ^ share_b`，**二进制中无明文密钥常量**（PoC-4 `check_key_constant.py` 验证） |
| **重构** | 运行时按需 `xor` 重构到临时缓冲；重构点分散、可结合 Step 混淆 |
| **使用** | 轮密钥扩展 → 加/解密；引用局部化 |
| **销毁** | 使用后 `secure_zero`（`volatile` 写，best-effort 抗内存转储）清零密钥与轮密钥 |

> **限制**：`secure_zero` 为 best-effort，不承诺抵抗专业冷启动/内存取证；此为威胁模型边界的一部分（§5）。

## 5. 威胁模型边界（**必须显式声明**）

- **定位**：**提高密钥/算法提取成本**，使「从代码中静态提取密钥」不再 trivial；**不承诺**抵抗专业 **DCA/侧信道/故障注入**（SRS §2.2 Won't）；
- **静态分析**：明文密钥、明文 S-box 规律在产物中不出现（PoC-4 证据）；
- **动态分析**：重构后的密钥会在内存短暂存在，属已知暴露面；通过分散重构点与用后清零提高成本；
- **不改变密码强度**：白盒实现与标准算法**输出一致**，安全性不依赖于算法被保密。

## 6. 与策略/预算集成（衔接 DD-02）

- 触发：`policy.assets[].strategies` 含 `white_box_crypto`（缺省 P0 关键资产）；
- 开销：DD-02 中 `base_cost(white_box_crypto)=0.03`（PoC-4 实测约 **1.05×**），`eff=0.15`；
- 合规：受 `compliance.crypto_strength_tier` 影响（CQ-02）。

## 7. 输出

- 由 `engine.protect` 产出：白盒实现文件/IR + 编码表生成器 + 份额常量；变换日志记录 `white_box_crypto(alg=aes, seed=…)`。

## 8. 复杂度与性能

- 加密：与标准 AES 同阶（编码引入常数级开销）；PoC-4 实测 **1.05×**；
- 表生成：`O(256)`/实例（一次性）。

## 9. 错误处理

| 情形 | 处置 |
| :--- | :--- |
| 不支持的算法/参数 | `E_TRANSFORM_FAILED`（或按策略降级到标准实现 + 告警） |
| 份额缺失/损坏 | 中止该资产变换（`E_TRANSFORM_FAILED`） |

## 10. 测试要点（移交 `dd-09-test-plan.md`，PoC-4 已提供基线证据）

| 项 | 用例方向 |
| :--- | :--- |
| 正确性 | FIPS-197 标准向量通过；加解密往返一致；1000 组随机一致性（PoC-4 ✅） |
| 无明文 | 二进制中不含明文密钥常量（PoC-4 ✅）；S-box 无明文规律 |
| 生命周期 | 使用后密钥/轮密钥被清零 |
| 开销 | 相对标准实现倍数在预算内（PoC-4 ✅ 1.05×） |
| 威胁边界 | 报告中显式标注「不抗 DCA/侧信道」 |
