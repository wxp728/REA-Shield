## 1. 项目概述

### 1.1 项目定位

Anti-REA Skill 是一个 AI Agent 可调用的**代码工程反逆向改造技能**。它接收代码工程（源码或二进制），自动施加多层级防护变换，使 REA（Reverse Engineer Anything）等 AI 驱动逆向工具无法有效还原源代码或功能逻辑，将攻击者的逆向成本推高至经济不可行的阈值以上。

### 1.2 设计哲学

**核心目标不是“让代码不可逆向”，而是“让逆向成本 > 逆向收益”。** 根据 Elastic Security Labs 的攻防经济学研究，传统混淆制造的是“保护时间 vs 逆向时间”的不对称，而 LLM 正在逆转这个不对称。本 Skill 的使命是重新扳回不对称，哪怕只是局部、暂时的。

### 1.3 参考对标

| 对标项目 | 参考价值 |
|:---|:---|
| **skill-guard** | 防御闭环设计：破坏“发现→工具路由→语义恢复→动态验证→跨版本复用”链路 |
| **Acoda** | 遗传算法驱动的对抗性混淆：迭代进化出越来越难被 LLM 分析的代码样本 |
| **SemAder** | 结构-语义联合诱导：生成功能保持但语义误导的二进制，使 LLM 功能判断偏移 |
| **Thales Sentinel Envelope Plus** | 生产级验证：保护后 AI 消耗 970 倍 Token 仍无法找到漏洞，最终放弃分析 |
| **Elastic Security Labs** | 攻防经济学数据：CFF+MBA 将 LLM 攻击成本提升 4.5 倍（$1.47→$6.60，8min→35min） |

## 3. 核心功能模块详细设计

### 3.1 模块一：输入分析层（Asset Scanner）

**功能描述**：自动扫描目标代码工程，识别需要保护的敏感资产。

**输入**：代码仓库路径、构建配置、可选的资产标注文件。

**处理逻辑**：

1. **工程类型识别**：自动检测语言（C/C++/Rust/Python/JavaScript/Java/.NET）、构建系统（CMake/Cargo/pip/npm/Gradle）、目标平台（Linux/Windows/Android/iOS/WASM）。
2. **敏感资产识别**：
   - 字符串扫描：API 密钥、Token、连接字符串、授权校验文本
   - 函数级分析：加密/解密函数、授权校验逻辑、算法核心
   - 数据流分析：密钥从生成到使用的完整路径
   - 配置扫描：`.env`、配置文件中的敏感字段
3. **敏感度分级**：
   - **P0（核心）** ：密钥管理、授权决策、专有算法
   - **P1（重要）** ：业务逻辑、协议实现、模型推理
   - **P2（一般）** ：UI 逻辑、工具函数、非核心流程
   - **P3（可忽略）** ：开源依赖、标准库调用

**输出**：`asset_manifest.json`，包含每个资产的路径、类型、敏感度等级和建议防护强度。

**边界条件**：
- 若工程包含开源组件，标记为 P3 并保留许可证声明，**不得**对开源部分施加混淆
- 若所有权不明或目标疑似恶意软件，**拒绝**执行并报告

### 3.2 模块二：策略决策层（Strategy Engine）

**功能描述**：根据资产清单和性能预算，生成防护策略组合。

**输入**：`asset_manifest.json`、性能预算配置、目标平台信息。

**处理逻辑**：

1. **策略库加载**：加载内置的策略模板库
2. **策略匹配规则**：

| 敏感度 | 推荐策略组合 | 预期性能开销 |
|:---|:---|:---|
| P0 | 代码虚拟化 + 白盒密码学 + 非线性 MBA + 对抗性诱导 | 15%-40% |
| P1 | 控制流平坦化 + MBA + 不透明谓词 | 5%-15% |
| P2 | 轻量混淆（标识符重命名、字符串加密） | 1%-5% |
| P3 | 无变换 | 0% |

3. **策略组合优化**：在安全强度和性能开销之间寻找 Pareto 最优解
4. **移动目标防御配置**：为 P0 资产启用多态变换，每次构建生成不同的保护变体

**关键决策依据**：
- Elastic Security Labs 数据：CFF+MBA 在 LLM 攻击成本提升上（4.5倍）优于 Virtualize+MBA（1.5倍）
- 但 VMP 在函数名恢复攻击下韧性最高，因此 P0 资产应采用**组合策略**而非单一策略

**输出**：`protection_policy.yaml`

```yaml
target:
  platform: linux-x86_64
  language: cpp
  build_system: cmake

performance_budget:
  max_overhead: 0.20  # 20% max acceptable overhead
  target_overhead: 0.10

assets:
  - path: src/crypto/key_manager.cpp
    sensitivity: P0
    strategies:
      - code_virtualization
      - white_box_crypto
      - non_linear_mba:
          order: 4
      - adversarial_inducement:
          framework: SemAder
    mtd:
      enabled: true
      variant_count: 8  # generate 8 variants per build

  - path: src/query/optimizer.cpp
    sensitivity: P1
    strategies:
      - control_flow_flattening
      - mixed_boolean_arithmetic
      - opaque_predicates

  - path: src/ui/*
    sensitivity: P2
    strategies:
      - identifier_renaming
      - string_encryption
```

### 3.3 模块三：变换执行层（Transform Engine）

这是 Skill 的核心执行模块，实现所有代码变换能力。

#### 3.3.1 子模块：LLVM IR 变换器

**功能**：在 LLVM IR 层实施编译级混淆变换。

**支持的变换**：

| 变换类型 | 技术描述 | 参考来源 |
|:---|:---|:---|
| 控制流平坦化 (CFF) | 将控制流图重构为 switch-case 调度器 | Tigress 兼容实现 |
| 非线性 MBA | 4阶 MBA 表达式，生成超过 124 万子句 | MBA-Blast 思路 |
| 不透明谓词 | 插入恒真/恒假的复杂数学表达式 | OLLVM 扩展 |
| 函数边界扰动 | 拆分/合并函数，破坏反编译器的函数识别 | 原创设计 |
| 数据流噪声注入 | 插入不影响语义的冗余数据操作 | 原创设计 |

**关键设计**：
- 所有变换必须保证**语义等价**，通过自动化测试验证
- 变换强度可配置（阶数、嵌套深度、冗余比例）
- 支持**选择性变换**：仅对 P0/P1 资产施加高强度变换

#### 3.3.2 子模块：代码虚拟化引擎

**功能**：将原生指令转换为自定义虚拟机字节码。

**架构设计**：

```
原始代码 → 自定义 ISA 设计 → 字节码编译器 → VM 解释器嵌入
```

**关键实现要点**：
- **自定义 ISA**：每个项目实例生成唯一的指令集（opcode 映射、寄存器分配方案均随机化）
- **VM 引擎**：解释器本身也施加混淆，防止攻击者通过分析 VM 理解被保护代码
- **多架构支持**：x86_64、ARM64、RISC-V（参考 ASGARD-5877 的多架构设计）
- **Pyraph 参考**：Native Mode 将源码编译为 C 并加密嵌入，运行时解密执行后立即内存擦除

**性能考量**：
- 虚拟化对性能影响最大（可达 2-5 倍开销），仅对 P0 资产的关键函数启用
- 提供“虚拟化覆盖率”参数，控制被虚拟化的代码比例

#### 3.3.3 子模块：对抗性诱导生成器

**功能**：生成功能保持但语义误导的二进制/代码变体。

**参考 SemAder 的三阶段流程**：

1. **控制流标记语料库构建**：标注代码的结构标签和语义特征
2. **混合相似度驱动的语料选择**：优先选择结构相近但语义背离的样本
3. **强化学习驱动的语义融合**：整合常量外部化和上下文感知语义增强

**关键数据**：
- SemAder 使 LLM 功能判断平均诱导差距达 **0.77**
- 使 CLAP 分类模型原类别置信度下降 **63.5%**，目标类别置信度上升 **68.9%**
- 二进制相似度检测器评分降至平均 **0.51**（接近随机）
- 仅带来 **12.7%** 平均二进制体积增长和 **8.8%** 平均运行时开销

**补充技术（参考 Acoda）** ：
- **Try-Except Wrapping**：将有效代码隐藏在 except 块中，诱导 LLM 误判执行条件
- **EOS Token 注入**：将 LLM 的结束标记包装为普通列表元素，诱导 LLM 在输出时遇到 EOS Token 而提前终止生成
- **遗传算法迭代**：维护混淆样本种群，选择对抗得分最高的样本进行交叉繁殖

#### 3.3.4 子模块：白盒密码学模块

**功能**：将密钥和算法逻辑“融化”在代码中，使攻击者无法从代码中提取密钥。

**适用场景**：客户端模型中的密钥管理逻辑、授权校验逻辑。

**实现思路**：
- 将 AES/SM4 的 S-box 嵌入为查找表，并通过编码变换隐藏查找模式
- 密钥与算法逻辑混合编码，密钥不以明文形式存在于任何内存位置
- 运行时密钥动态重构，使用后立即销毁

### 3.4 模块四：构建集成层（Build Integration）

**功能**：将 Anti-REA Skill 嵌入现有 CI/CD 流程。

**支持的集成方式**：

| 集成方式 | 描述 | 适用场景 |
|:---|:---|:---|
| CLI 工具 | 独立命令行工具，可通过脚本调用 | 任何构建系统 |
| CMake 插件 | 作为 CMake 的编译后步骤 | C/C++ 项目 |
| Cargo 插件 | 作为 Rust 的构建后处理 | Rust 项目 |
| npm 脚本 | 作为 package.json 的 postbuild 钩子 | JavaScript/TypeScript |
| Python 包 | 作为 setup.py 的 build_ext 扩展 | Python 项目 |
| MCP Server | 作为 AI Agent 可直接调用的 MCP 工具 | Agent 集成 |

**构建流程**：

```
源码 → 标准编译 → 中间产物 → [Anti-REA 变换] → 保护产物 → 功能验证 → 打包分发
```

**关键配置项**：

```yaml
build:
  hooks:
    pre_transform: scripts/pre_scan.sh
    post_transform: scripts/post_verify.sh
  
  verification:
    run_tests: true
    test_command: "ctest --output-on-failure"
    abort_on_failure: true

  output:
    report_format: [json, html, markdown]
    report_path: "./protection_reports/"
```

### 3.5 模块五：评估验证层（Evaluation & Verification）

**功能**：量化评估防护效果，验证功能保持。

#### 3.5.1 功能保持验证

- **自动化测试套件**：运行目标工程的全部单元测试和集成测试
- **模糊测试**：对关键接口进行随机输入测试，确保变换后行为一致
- **性能基准测试**：测量变换前后的运行时开销，确保在预算范围内

#### 3.5.2 AI 攻击模拟

**核心设计**：Skill 内置一个“攻击模拟器”，自动调用主流 LLM 和逆向工具对保护后的产物进行攻击，量化防护效果。

**模拟攻击流程**：

1. **静态分析攻击模拟**：调用 Ghidra/IDA 的反编译能力 + LLM 语义恢复
2. **动态分析攻击模拟**：沙箱中运行受保护代码，尝试内存转储和调试
3. **跨版本复用攻击模拟**：用旧版本训练 LLM，测试对新版本的攻击效果

**量化指标**（参考 Elastic Security Labs 的评估框架和 lumevalley 白皮书）：

| 指标 | 定义 | 目标值 |
|:---|:---|:---|
| **Token 消耗倍数** | AI 分析保护产物的 Token 消耗 / 分析未保护产物的 Token 消耗 | ≥ 500x |
| **分析时间倍数** | 同上，时间维度 | ≥ 10x |
| **函数名恢复准确率** | LLM 恢复正确函数名的比例 | ≤ 20% |
| **功能判断准确率** | LLM 正确判断函数功能的比例 | ≤ 30% |
| **漏洞发现率** | AI 发现的真实漏洞数 / 总漏洞数 | ≤ 10% |
| **二进制相似度评分** | BinDiff/Asm2Vec 等工具的相似度评分 | ≤ 0.55 |

#### 3.5.3 回归检测

每次 Skill 更新或策略调整后，自动运行攻击模拟基准测试，确保新策略没有引入新的弱点。维护一个“**防护效果时间序列数据库**”，追踪各项指标随时间的变化趋势。

### 3.6 模块六：对抗策略引擎（Adaptive Strategy Engine）

这是 Skill 区别于传统加固工具的核心——**用 AI 来对抗 AI，并且持续进化**。

**工作流程**：

            ┌─────────────┐

**关键能力**：
- **多 LLM 并行探测**：同时调用 Claude、GPT、Gemini 等多个模型，评估策略的跨模型泛化能力
- **策略遗传进化**：维护策略种群，选择防护效果最好的策略进行交叉变异
- **迁移学习**：将一个项目的有效策略迁移到相似项目，减少冷启动时间

## 4. 技术选型

| 组件 | 推荐技术 | 备选方案 | 理由 |
|:---|:---|:---|:---|
| IR 层变换 | LLVM 18+ | MLIR | 生态成熟，C/C++/Rust 支持好 |
| 虚拟化引擎 | 自研（参考 ASGARD-5877） | Tigress | 自研可获得差异化能力 |
| 遗传算法框架 | DEAP（Python） | 自研 | 快速原型，成熟稳定 |
| LLM 调用 | MCP 协议 | OpenAI API | 与 AI Agent 生态无缝集成 |
| 攻击模拟 | Ghidra Headless + LLM | IDA Pro + LLM | Ghidra 开源可自动化 |
| 构建集成 | CMake/Cargo 插件 | Makefile 钩子 | 覆盖主流构建系统 |
| 配置管理 | YAML + JSON Schema | TOML | 可读性好，工具链成熟 |

### Phase 2：核心能力（第 5-10 周）

## 6. 关键风险与应对

| 风险 | 影响 | 应对措施 |
|:---|:---|:---|
| 虚拟化性能开销过大 | 产品不可用 | 提供覆盖率参数，仅保护关键函数；性能预算预测器提前评估 |
| LLM 能力快速提升 | 策略失效 | 对抗策略引擎持续进化；维护多套策略，自动切换 |
| 开源组件被误保护 | 许可证违规 | 资产扫描阶段标记开源组件为 P3，跳过变换 |
| 攻击者绕过保护 | 源码泄露 | 纵深防御设计，单层失效不影响整体；持续监控和响应 |
| 误报被安全软件拦截 | 分发受阻 | 提供签名和申诉流程支持；与主流 EDR 厂商建立白名单机制 |
| 出口管制合规 | 法律风险 | 根据目标市场自动调整加密强度；保留合规审计日志 |

## 7. 与现有工作的差异化定位

现有工作中，skill-guard 聚焦于**防御策略的决策与验证**，Acoda 和 SemAder 是**学术界的单点技术**，Thales Sentinel Envelope Plus 是**闭源商业产品**。本 Skill 的差异化在于：

1. **端到端流水线**：从资产扫描到策略决策、变换执行、构建集成、评估验证的完整闭环，而非单点工具
2. **AI 驱动的自适应防御**：内置对抗策略引擎，持续探测 LLM 弱点并自动调整策略
3. **与全密态数据库的协同**：P0 资产的变换产物可进一步放入 TEE 或全密态数据库的保护域中，形成“代码保护 + 数据保护”的纵深体系
4. **攻防经济学导向**：以“Token 消耗倍数”和“分析时间倍数”为核心指标，而非追求“不可破解”的理论目标
